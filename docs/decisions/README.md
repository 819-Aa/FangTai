# V2架构决策登记

- 状态：`APPROVED`
- 日期：2026-08-09
- 适用项目：`program_v2`

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| `CONFIRMED` | 已进入V2目标架构，后续模块设计和实现必须遵守 |
| `DEFERRED` | 已明确不阻塞当前核心建设，并规定重新评估时点 |
| `REJECTED` | 已讨论并明确不采用，除非发起新的架构变更重新审查 |
| `SUPERSEDED` | 已被后续批准决策取代，只保留历史追溯，不再授权实现 |

本登记只记录全局选择。需要完整背景、替代方案和影响分析的决策另建ADR，并在本文件中链接。

## 2. CONFIRMED：已确认决策

| ID | 决策 | 对后续工作的约束 |
|---|---|---|
| DEC-C001 | 使用与旧`program`并列的`program_v2` | 旧系统在V2验收前保持可运行；详见[ADR-0001](0001-v2-workspace-and-migration.md) |
| DEC-C002 | V2采用模块化单体 | 模块在同一工程部署，但遵守数据所有权、公开接口和单向依赖 |
| DEC-C003 | 健康硬排除以标准食材精确关系命中为准 | 通用关系固化为`constraint_code → ingredient_id`；任一标准食材命中任一参与者有效健康硬约束时排除整道菜 |
| DEC-C004 | 多人菜单采用全员健康交集 | 每道共享菜必须对所有参与者通过健康审查，不生成个人专属菜 |
| DEC-C005 | RAG只负责召回用户想要的真实菜品 | RAG不读取健康档案、不执行健康审查、不输出安全结论 |
| DEC-C006 | RAG使用完整混合检索 | 词法、向量、加权融合和重排序为完整链路，不使用纯词法降级 |
| DEC-C007 | 营养只参与内部软排序 | 不触碰健康硬筛选，不在正常回答和前端展示营养数值 |
| DEC-C008 | 不计算烹饪营养损耗 | 内部营养依据批准的原始食材参考计算；来源只留在离线参考/审阅文件，运行时营养 Artifact 不含来源或置信度 |
| DEC-C009 | 不处理分量和采购量 | 移除`per_serving`、个人摄入、人数份量、采购量和参与者营养汇总 |
| DEC-C010 | 时间采用 source-authoritative 步骤任务图 | 区分主动操作、设备占用和被动等待；完整图由 CP-SAT 产生预计单值，详见 [ADR-0007](0007-estimated-task-graph-time-semantics.md) |
| DEC-C011 | legacy 保留五角色，新模式采用受约束的行动选择角色 | legacy 维持原职责；新模式由业务 Agent 选择合法动作并通过受控步骤生成回答，详见 [ADR-0008](0008-langgraph-hybrid-agent-orchestration.md) |
| DEC-C012 | 不增加权限管理模型 | 角色权限、工具白名单和合法转移由代码定义；Agent 可在边界内选择业务动作，不能动态分配权限 |
| DEC-C013 | 模型在角色白名单内自主调用工具 | 模型主动决定调用时机；必需回执是角色完成条件，工作流不预调用或漏调后补调用，可选工具由模型判断，禁止工具不暴露 |
| DEC-C014 | 模型不能直接修改WorkflowState | 模型只生成Artifact，由工作流校验后更新State |
| DEC-C015 | 模型间使用受控共享上下文通信 | 使用`SharedWorkflowContext`、类型化Artifact和`HandoffMessage`，不共享隐藏思维过程 |
| DEC-C016 | Agent工作流不设置回答兜底 | 不使用固定答案、回答模板降级或缺失工具后的继续执行 |
| DEC-C017 | 不执行技术自动重试和自动模型切换 | SDK、工具、存储和提交失败直接暴露；业务修订按固定上限执行 |
| DEC-C018 | 核心上下文不可静默压缩 | 当前消息、健康约束、当前菜单和待澄清事项始终保留 |
| DEC-C019 | 固定原始数据仍执行完整离线处理 | 原始菜品和用户健康档案不能由Agent直接解析，必须先完成标准化、关系构建和质量验证 |
| DEC-C020 | 不建设运行时数据发布和版本切换机制 | 项目数据确定；只保留离线全量构建、存储初始化和质量门禁 |
| DEC-C021 | 最终回答只描述已验证事实 | 不添加菜品、不改写食材、不展示内部营养值、不输出医疗效果 |
| DEC-C022 | 用户可见分析是证据摘要 | 展示已验证的处理依据，不输出隐藏思维链或系统日志 |
| DEC-C023 | API采用请求和事件分离 | 一个异步执行入口，状态查询、SSE和取消围绕同一`request_id`工作 |
| DEC-C024 | 最终结果与强制健康审计原子提交 | 强制审计失败时回滚，不保留`completed`结果 |
| DEC-C025 | 先完成总设计再逐模块详设和实现 | 所有模块引用共享契约和全局不变量，不孤立推进 |
| DEC-C026 | 对话不能覆盖永久健康硬约束 | 临时信号可以新增约束或撤销本会话自己的临时约束，但不能删除、放宽或忽略固定档案约束 |
| DEC-C027 | 可选和替代食材按并集参与健康审查 | 不通过删去可选项或自动选择替代项改变原菜谱；食材替换必须形成独立、完整审查的菜品变体 |
| DEC-C028 | 健康PASS必须建立在固定食材全集的完整关系覆盖上 | 每个允许`constraint_code × ingredient_id`都要有唯一批准决定，审核键集合与健康食材全集精确相等；覆盖缺失或不完整进入`failed` |
| DEC-C029 | 健康引擎使用二元结果并对最终菜单重新计算 | B4只输出`PASS/EXCLUDE`；菜单决策选择已有`plan_id`后主动调用同一引擎重新校验，系统错误不进入菜单重新规划 |
| DEC-C030 | 菜品源固定为经精确清单核验的 2,000 行 | `recipe_id=1..2000` 与源行绑定；每行必须显式分类且零未决；详见 [ADR-0004](0004-fixed-source-and-one-time-identity-rebuild.md) |
| DEC-C031 | 一次性重建并冻结 V2 食材身份 | 当前污染 ID 不继承；形成 merge/split/discard crosswalk，经审核后运行时不得动态增删身份；详见 [ADR-0004](0004-fixed-source-and-one-time-identity-rebuild.md) |
| DEC-C032 | B1 是原始菜品和食材文本的唯一解析者 | B3/B4/B5/B6/C1 只消费同一构建的结构化 Artifact，在线禁止读取离线文件 |
| DEC-C033 | 预计时间与更快偏好使用不同语义 | 在线为单个预计 makespan 与布尔可行性；固定构建缺图属于系统失败；详见 [ADR-0007](0007-estimated-task-graph-time-semantics.md) |
| DEC-C034 | 软评分维度不可用时显式禁用并重归一化 | 不使用默认 0.5、零值或模型猜测伪装中性证据 |
| DEC-C035 | 成功事件只能引用已提交结果 | 结果、强制审计和 outbox 原子提交，之后发布 `answer_ready/result_committed`；详见 [ADR-0006](0006-post-commit-event-publication.md) |
| DEC-C036 | DeepSeek 整改采用外部阶段闸门 | 模型可选局部写法，但不能修改任务信封、锁定测试和批准契约；偏离不能进入下一阶段 |
| DEC-C037 | C3 采用受约束的 Agent 工具编排 | LangGraph 承载行动—工具反馈循环；模型选择下一步，代码强制证据、预算与提交边界，禁止自动放宽硬约束；详见 [ADR-0008](0008-langgraph-hybrid-agent-orchestration.md) |

[ADR-0003](0003-implementation-round-2-deviations.md) 已于 2026-08-09 标记为 `SUPERSEDED`。其中 C3 自动节点重试、LLM 时间高权威化、40% 并行公式和严格时间软化均不得继续作为设计依据。

## 4. REJECTED：明确不采用的路径

| ID | 不采用的路径 | 原因 |
|---|---|---|
| DEC-R001 | 原地清空或重置旧`program` | 缺少有效旧Git历史，会失去可运行基线和新旧对照 |
| DEC-R002 | 在`program/next`中嵌套新工程 | 两套Python包、前端、依赖和测试发现规则会互相干扰 |
| DEC-R003 | 当前拆分微服务 | 增加网络、部署和分布式事务复杂度，模块化单体已经满足当前边界需求 |
| DEC-R004 | 使用管理模型分配角色、权限或工具 | 系统控制会依赖不确定输出，并产生管理模型自身的审查循环 |
| DEC-R005 | 让RAG直接判定用户健康安全 | 检索相关性不能替代标准食材、健康约束和审核规则 |
| DEC-R006 | 用纯字符串包含推断食材健康硬关系 | 会产生“海鲜菇”“红酒醋”“素蚝油”等名称误判 |
| DEC-R007 | 用低置信度营养估算触发健康红线 | 营养估算只具备辅助比较价值，不能替代食材硬关系 |
| DEC-R008 | 使用烹饪损耗模型修正当前营养值 | 当前数据不足以支持稳定科学的损耗计算，且营养仅用于软排序 |
| DEC-R009 | 健康筛选失败后继续生成固定回答 | 会掩盖必需工具、证据或工作流错误，违反失败可见原则 |
| DEC-R010 | 自动切换模型或无限重试 | 会重复执行工具、扩大成本和隐藏根因，破坏有界工作流 |
| DEC-R011 | 多人菜单只保证部分参与者可食用 | 与共享菜单的全员健康交集原则冲突 |
| DEC-R012 | 模型之间完全隔绝 | 会丢失必要公共事实和执行上下文；采用受控共享而非自由聊天 |
| DEC-R013 | 在Qdrant保存聊天向量记忆 | 健康和会话事实需要结构化优先级、版本和可撤销语义，不适合由相似度决定 |
| DEC-R014 | 前端自行生成业务分析或健康说明 | 前端缺少权威证据和工作流状态，容易与后端结果不一致 |

## 5. 决策变更规则

- 修改`CONFIRMED`决策必须评估受影响的全局不变量、模块边界、场景和模块详设。
- 启用`DEFERRED`能力时必须新建ADR，明确它是否进入主流程、失败是否影响结果以及隐私边界。
- 重新采用`REJECTED`路径时必须说明原拒绝理由为何不再成立。
- 决策更新与受影响文档在同一个逻辑提交中完成，不能只改实现不改决策记录。
