# ADR-0004：固定源数据与一次性身份重建

- 状态：`CONFIRMED`
- 日期：2026-08-09
- 适用范围：B1、B3、B4、B5、B6、C1、数据库初始化与迁移

## 背景

V2 的菜品全集固定为项目内 `data/raw/recipes_sample_2000.csv`。该文件以后不会增加、减少或在线更新，但当前实现产生了不可靠的食材身份、重复解析、运行时读取离线文件、分类未闭合和下游派生产物互不一致等问题。旧 `program` 的处理方式只可作为候选规则来源，不能覆盖 V2 的模块边界和契约。

固定数据降低了发布系统的复杂度，但不会自动保证数据正确。系统仍需在一次性重建时形成完整、可审核、可重复的权威事实，并在运行时只消费这些已验证事实。

## 决策

### 1. 固定源清单

菜品源的唯一合法清单为：

| 字段 | 固定值 |
|---|---|
| 路径 | `data/raw/recipes_sample_2000.csv` |
| 编码 | `GBK` |
| 文件大小 | `1,138,083` bytes |
| SHA-256 | `B2177DC6CDCAE24FC5671C8DADA44295228F4301E3CE620ED11D51B1ABFE4371` |
| 数据行数 | `2,000`，不含表头 |
| 表头 | `名称`、`食材清单`、`烹饪步骤`、`label` |

任何字段不匹配都必须以 `SOURCE_MANIFEST_MISMATCH` 停止构建，不得自动接受新版本、猜测编码或继续使用部分结果。

### 2. 固定菜品身份

- `recipe_id` 取值固定为 `1..2000`，与源文件数据行位置一一对应。
- 构建必须逐行产生解析结果和显式分类，不允许静默丢行、合并行或重新编号。
- 每行恰好属于一个批准的 `record_type`。初始候选分类可以借鉴旧 `program`，但最终分类必须由 V2 规则生成、人工审查清单确认并通过零未决门禁。
- 非菜品记录可以从推荐视图排除，但必须保留其源行身份、分类原因和审查证据。

### 3. 一次性重建食材身份

- 当前 V2 生成的食材 ID 不视为可继承权威事实；执行一次完整重置和重建。
- B1 必须产出原始词条到标准食材的 `merge / split / discard` 交叉表，所有 2,000 行中的食材出现都必须可追溯。
- 标准食材 ID、审核别名、类别、食材族和来源证据在审核通过后冻结。
- 构建结束时不允许存在未解析的推荐食材、模糊创建的新身份、同一词条多重映射或无证据的自动合并。
- 后续运行时不得自动新增、删除或重编号食材。任何修订必须作为新的显式 ADR 和全量重建处理；本项目默认不会发生该修订。

### 4. B1 是唯一解析者

- 只有 B1 可以读取并解析原始菜品 CSV、原始食材字符串和原始步骤字符串。
- B3、B4、B5、B6、C1 只能消费 B1 通过 Schema、清单和质量门禁发布的结构化产物。
- 在线运行时只能读取 MySQL、Qdrant 和受契约约束的 Repository，不得读取 CSV/JSONL 构建文件，也不得重新解析原始文本。

### 5. 单次构建与原子初始化

- 不建设运行时数据版本切换、双读或自动发布平台。
- 离线构建先写入隔离的 staging 目录和 staging 存储；全部质量门禁通过后，才允许一次性初始化空的 V2 数据库与 Qdrant 集合。
- 初始化必须验证源清单、Artifact 清单、记录计数、主外键、健康关系覆盖、索引计数与散列。
- 任一门禁失败都不得留下“部分可用”的生产数据；不得在在线请求中回退到旧文件或旧 `program`。

### 6. 旧系统边界

- `program` 保持只读参考和对照基线；不得修改、移动或删除。
- 可以借鉴其解析候选、异常样本和测试用例，但每条规则必须重新进入 V2 契约、测试和审查。
- V2 的食材 ID 不需要与 V1 相同；需要对照时使用显式 crosswalk，不得用数值相等推定同一身份。

## 强制门禁

构建成功必须同时满足：

1. 源清单完全匹配；
2. 2,000 个 `recipe_id` 连续且唯一；
3. 2,000 行均有唯一 `record_type`，未决数为 0；
4. 所有进入推荐视图的食材出现均映射到唯一标准食材；
5. 所有允许的 `constraint_code × ingredient_id` 均有独立、人工批准的决定；
6. B3/B4/B5/B6/C1 产物共享同一 `source_manifest_hash` 与 `build_id`；
7. MySQL 与 Qdrant 的计数、引用和散列一致；
8. 初始化前后均有可机器核验的证据文件。

## 影响

- 优点：身份和全链路事实只重建一次，在线系统无需处理动态数据演进；下游不会各自解释同一原始字符串。
- 成本：必须放弃当前污染的食材注册表并完成一次人工审查；在所有门禁通过前，V2 不得宣称数据链路可用。
- 回滚：staging 失败时只删除本次 staging 产物；生产初始化失败时回滚整个初始化事务并删除未发布的 Qdrant staging 集合。不得回滚或覆盖旧 `program`。
