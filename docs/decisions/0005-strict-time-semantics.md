# ADR-0005：严格时间与软时间偏好的语义

- 状态：`CONFIRMED`
- 日期：2026-08-09
- 适用范围：查询理解、B5、C2、C3、回答和前端

## 背景

用户表达的“30 分钟内必须完成”和“尽量快一点”不是同一种约束。当前实现曾允许离线 LLM 时间估算和简化并行公式影响严格时间结论；这种估算可以辅助排序，但不能证明一个菜单一定满足硬截止时间。

## 决策

### 1. 两类意图必须分离

- `strict_time_feasibility_required=true` 表示硬截止时间，必须有分钟数且只能由高权威确定性调度证明。
- `prefer_faster=true` 表示软偏好，可以没有硬截止时间，只参与安全候选之间的排序。
- 查询语义不明确时不得擅自把软偏好升级为硬约束。

### 2. B5 使用三值证据

`strict_time_feasible` 的值为：

- `true`：高权威任务图和资源调度证明 `makespan <= deadline`；
- `false`：高权威任务图和资源调度证明 `makespan > deadline`；
- `unknown`：缺少步骤时长、依赖、设备或并发事实，不能形成硬结论。

每个结论都必须包含 `schedule_hash`、`time_source`、`confidence`、缺失事实和证据引用。

### 3. C2 的接受规则

- 硬截止时间请求只能接受 `strict_time_feasible=true` 的菜单。
- `false` 和 `unknown` 都不得被描述为“满足时限”。
- 候选均为 `false` 时返回 `NO_FEASIBLE_MENU`。
- 仍存在 `unknown` 且没有任何 `true` 时返回 `STRICT_TIME_INDETERMINATE`，如实说明缺失证据；不得自动放宽截止时间或用软估算冒充可行。

### 4. 模型估算的权限

- LLM 生成的离线时间估算只能作为 `model_estimate` 软证据和排序特征。
- `model_estimate` 永远不能获得严格时间的高权威资格，也不能把 `unknown` 改为 `true` 或 `false`。
- 固定比例并行公式、菜品总时长简单求和和经验常数只能用于调试或低权威软排序，不能进入严格可行性证明。

### 5. 用户可见语义

- 前端必须区分“已验证满足时限”“无法验证时限”“未找到满足时限的菜单”和“按更快偏好排序”。
- 回答模型只能复述结构化时间证据，不得自行估算或承诺完成时间。
- 时间不可用不等于健康失败；系统应保留准确的独立终态与错误码。
