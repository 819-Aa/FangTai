# ADR-0001：建立并列的V2工作区并逐模块迁移

- 状态：已批准
- 日期：2026-08-04
- 范围：项目目录、文档组织、迁移方式和Git提交边界

## 背景

旧项目`program`已经包含数据管道、健康规则、RAG、菜单优化、LangGraph工作流、API、前端和测试，不适合视为空项目重做。同时，旧实现存在较大的核心文件和跨层依赖，直接原地重构会增加破坏现有能力和丢失对照基线的风险。

工作区根目录下虽然存在`.git`目录，但其中没有可用仓库元数据，无法依靠现有版本历史完成可靠恢复。因此，新系统需要独立的版本基线。

## 决策

在旧项目旁建立`program_v2`：

```text
竞赛/
├── program/       # 旧系统，迁移期间保持可运行
└── program_v2/    # 新文档、新架构和新实现
```

V2采用模块化单体。所有模块在同一个后端工程中部署，但遵守明确的数据所有权、公开接口和单向依赖。当前阶段只创建工作区、文档体系和边界说明，不迁移业务代码。

## 选择理由

### 相比原地重构

- 保留旧系统作为行为和数据对照。
- 避免在缺少有效Git历史时覆盖可运行实现。
- 允许新架构从共享契约和模块边界开始建设。
- 新系统验收前不影响旧系统运行。

### 相比在`program/next`中嵌套新工程

- 避免两套Python包、依赖、前端和测试发现规则互相干扰。
- 新旧工程可以使用独立的运行配置和版本历史。
- 最终切换时不需要从旧工程内部剥离嵌套项目。

### 相比拆分微服务

- 当前规模不需要网络化模块协作和分布式事务。
- 模块化单体已经能够提供职责隔离、独立测试和内部可替换性。
- 避免增加部署和运行复杂度。

代码目录将在对应模块设计获批后逐步建立，不通过空代码文件制造虚假的完成状态。

## 新旧系统隔离

迁移期间遵守以下边界：

- 旧项目原则上冻结，只用于运行、审查和结果对照。
- 新文档和新实现只写入`program_v2`。
- 不整体复制旧项目的`src`、前端或派生数据。
- 不复制`.venv`、`node_modules`、模型缓存和运行日志。
- 新旧系统使用不同的MySQL数据库、Qdrant Collection、Redis前缀和API端口。
- V2可以只读复用项目内确定的原始输入，但必须独立生成并验证自己的清洗数据、MySQL初始化数据、RAG文档和Qdrant索引。
- 原始输入数据可以作为只读来源复用；V2处理结果必须独立生成。

## 模块迁移分类

每个旧模块在迁移前必须被归入以下一种状态：

| 状态 | 含义 |
|---|---|
| `REUSE` | 职责和实现均符合新设计，可在验证后复用 |
| `REFACTOR` | 核心逻辑可用，但需要拆分职责或解除依赖 |
| `REWRITE` | 与新契约或系统边界冲突，需要重新实现 |
| `REMOVE` | 新系统不再需要，不迁移 |
| `PENDING` | 已明确推迟决定，不阻塞当前核心建设 |

迁移顺序为：模块详设、旧实现审查、分类、实现、模块测试、跨模块测试、新旧结果对照。

## Git提交规则

`program_v2`建立独立Git仓库，默认分支为`main`。一次提交只包含一个可以独立理解、验证和回退的逻辑块。

提交消息使用：

```text
<type>(<scope>): <description>
```

主要类型为`chore`、`docs`、`feat`、`refactor`、`fix`、`test`、`build`、`perf`和`cleanup`。实现代码原则上与对应测试一起提交；共享契约先于其消费者提交。密钥、健康档案原文、依赖目录、模型缓存、运行数据和未选作基线的生成物不得提交。

第一笔提交为：

```text
chore(repo): initialize modular v2 workspace
```

## 实施顺序

```text
系统总设计
→ 共享契约
→ 数据工程模块
→ 确定性业务工具
→ WorkflowState与Artifact
→ 五模型工作流
→ 上下文与记忆
→ API与SSE
→ 前端
→ 全链路验收
→ 旧项目清理
```

## 旧项目退出条件

只有同时满足以下条件，才审查归档或删除旧项目：

- 全局不变量全部通过自动验证。
- 食材健康硬筛选案例全部通过。
- 五模型工作流及其工具权限完整运行。
- 多人健康交集和多轮上下文场景通过。
- API、SSE和前端完成并通过验收。
- 新旧关键场景对照完成。
- 不再存在依赖旧项目的消费者或在途请求。

旧项目退出属于单独的受控变更，不在V2初始化阶段执行。

## 影响

正面影响是获得可恢复的新版本历史、清晰的模块边界和稳定的新旧对照。代价是迁移期间暂时维护两个工程，并需要为服务和派生数据设置隔离命名空间。该代价在V2验收并退出旧项目后结束。
