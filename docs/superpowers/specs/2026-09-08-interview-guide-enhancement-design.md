# 面试问题文档增强设计

## 目标

在不继续堆砌题目数量的前提下，将现有《方太个性化健康膳食推荐 Agent：面试问题与参考回答》增强为一份可直接用于技术面试准备的“深挖防守版”材料。

增强后的文档需要同时做到：

- 能用 30 秒和 90 秒两种长度介绍项目；
- 能从业务问题自然过渡到关键技术设计；
- 面试官追问实现细节时，回答有代码事实和数据支撑；
- 对没有实现的生产级能力保持准确边界，不夸大项目成熟度；
- 仍然便于阅读和背诵，不把文档扩展为通用八股题库。

## 现有问题

现有文档已经覆盖语义理解、混合检索、健康审核、上下文、记忆、一致性和可靠性，但部分回答主要说明“为什么这样设计”，缺少以下内容：

1. 一条具体用户请求如何穿过完整工作流；
2. 超时、模型异常、重复请求、锁过期和事件发布失败时的实际处理；
3. 项目数据规模、关键检索参数和可展示的验证证据；
4. 面试中不同时间限制下的表达方式；
5. 面试官质疑“是否过度设计”时的取舍依据。

## 内容设计

### 1. 增加分层项目介绍

在题库前增加两种开场口径：

- 30 秒版本：只讲场景、主链和核心设计边界；
- 90 秒版本：补充数据建模、检索、双重健康校验和多轮状态管理。

两个版本保持事实一致，避免背诵时出现两套架构描述。

### 2. 增加端到端场景拆解

使用“不要花生，并把第二道菜换成清淡一点的”作为统一案例，依次说明：

1. 读取当前菜单及会话上下文；
2. 千问识别操作类型、目标位置和新增约束；
3. 生成并校验 QueryPlan；
4. 合并永久健康约束和本轮临时约束；
5. 召回替换候选并完成健康审核；
6. 保留未修改菜品，只替换目标位置；
7. 对整份新菜单进行最终健康校验；
8. 使用幂等、fencing token 和事务 Outbox 完成版本化提交。

该案例用于串联语义理解、检索、健康、上下文、记忆和一致性，不额外虚构一套流程。

### 3. 补充真实实现细节

在现有问题中按需加入以下事实：

- QueryPlan 使用 Pydantic 严格校验并禁止额外字段；
- 语义重写调用具有短超时，失败后使用确定性结果兜底；
- BM25 和向量检索分别召回候选，通过 RRF 融合后使用 BGE 重排；
- Qdrant 使用 `build_id` 等 Payload 条件隔离数据版本；
- 提交阶段校验请求身份、参与者、菜单哈希、健康结论和 fencing token；
- Outbox 通过稳定事件 ID、领取令牌和租约支持失败重放；
- OR-Tools 用于烹饪任务图的时间可行性计算，不负责直接选菜。

只加入能够从当前项目代码或文档确认的事实，不编造效果提升比例。

### 4. 增加异常场景速查表

新增紧凑表格，覆盖：

- 模型超时或输出不合法；
- Qdrant 不可用；
- 无安全候选；
- 重复请求；
- 会话锁过期后旧任务继续执行；
- 数据库提交后事件发布失败；
- MySQL 与 Qdrant 数据版本不一致；
- 用户主动取消请求。

每个场景说明当前处理方式、保护目标和项目边界。

### 5. 增加数据与证据口径

增加一份“可主动说、被问再说、不能乱说”的证据清单：

- 可主动说：菜谱、标准食材、关系矩阵和向量点的固定数据规模；
- 被问再说：测试类型、质量门禁、真实多轮会话覆盖；
- 不能乱说：未测量的准确率、吞吐量、延迟收益和商业指标。

### 6. 增加取舍与反质疑回答

重点增加三个容易被挑战的问题：

- 只有约两千道菜，为什么还需要向量库？
- Artifact、Manifest、Outbox 是否过度设计？
- 为什么不用一个大模型完成全部工作？

回答需要承认当前规模，同时说明这些设计分别服务于语义召回、健康安全和状态一致性；不以“生产级”作为包装理由。

## 文档结构

正式文档调整为：

1. 使用说明与统一主线；
2. 30 秒和 90 秒项目介绍；
3. 一条请求的端到端执行案例；
4. 高频问题与参考回答；
5. 异常场景速查表；
6. 项目数据和验证证据；
7. 面试统一口径与回答雷区；
8. 面试前优先准备顺序。

原有 30 个问题原则上保留，通过合并重复表达和补充细节提高质量，不增加无关的 FastAPI、MySQL 或 Docker 通用八股题。

## 质量标准

- 所有技术表述与当前 README 和实现一致；
- `fast_path` 明确包含一次模型语义理解；
- 不将 Qdrant 描述为健康裁决组件；
- 不将 OR-Tools 描述为主菜单选择器；
- 不将 Redis 描述为持久事实来源；
- 不宣称系统具备完整生产级高可用；
- 不使用没有测试证据的效果数字；
- 文档无 TODO、占位文本或互相矛盾的描述。
